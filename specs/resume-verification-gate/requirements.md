# 简历交付验收闸门需求

## 问题

Agent 可能在完成写入或生成预览后直接结束任务，而没有读取真实 A4 页数、溢出和信息密度指标。提示词只能引导，不能保证调用顺序；同时草稿迭代不应被验收闸门阻塞。

## 用户故事

- 作为 Agent，我需要知道当前简历是草稿、待测量、需要返工还是已验收，才能按工序继续。
- 作为用户，我希望 Agent 可以自由重写和迭代内容，但不能把未测量或两页简历声称为完成。
- 作为 DSH，我需要把浏览器测量失败、过期预览和指标缺失显式反馈给 Agent，而不是静默丢失。

## 验收标准（EARS）

1. 当 `resume_write` 或模板/呈现变更完成时，系统应将会话标记为 `draft`，并返回下一步为读取、检查、渲染、测量；不得返回已完成。
2. 当 `resume_render` 完成但没有匹配当前渲染身份的浏览器指标时，系统应返回 `verification_pending`，并明确要求调用 `resume_metrics`；不得允许最终验收。
3. 当 Agent 调用最终验收工具时，系统应同时要求当前内容已检查、当前预览已渲染、指标可用且匹配当前 renderId/contentHash。
4. 当真实指标为一页、无溢出、信息密度可读且核心证据保留时，最终验收工具应返回 `accepted` 和 `completionAllowed=true`。
5. 当指标待回传、超过一页、溢出或一页但稀疏时，最终验收工具应返回 `blocked`，说明原因和下一步；不得伪造页数或通过状态。
6. 当验收通过后简历或模板再次发生变更时，系统应立即使验收失效，回到 `draft`，要求重新检查、渲染和测量。
7. 当浏览器指标 POST 失败或身份不匹配时，预览运行时和 DSH 面板应暴露可诊断错误，不得使用空 catch 静默吞掉。

## 业务约束

- 闸门只约束“最终完成/导出前声明”，不阻止用户或 Agent 继续迭代草稿。
- 一页 A4 是硬目标；实习、教育和选定项目的核心证据受保护，压缩顺序继续由现有简历指南负责。
- 独立 stdio MCP 没有浏览器时可以 pending，但必须明确告诉调用方打开 HTTP 预览运行时。

## 非目标

- 不在本次改动中自动替用户删改简历内容。
- 不改变现有工作区绑定、模板副本和 DSH 原有编辑入口。
