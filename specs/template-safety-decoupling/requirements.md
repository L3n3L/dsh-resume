# 模板改造与简历版本解耦需求

## 问题

用户选择一个模板加入简历时，模板应成为当前简历的视觉基线。Agent 可以基于它重构布局、模块承载、视觉层级和 CSS，让内容更饱满，但不能因为排版困难就静默换成另一个模板，也不能无意中修改其他简历正在使用的共享模板。

当前风险是：模板结构保存、工作区级排版覆盖和简历版本之间的边界不够清晰。提示词即使写明了“复制后修改”，不遵守提示词的 Agent 仍可能用同一自定义模板 ID 覆盖共享模板，或把排版参数写成同模板下所有简历共用的设置。

## 用户故事

- 作为用户，我选择“校招标准”模板后，希望 AI 在这个风格上补足信息密度，而不是换成商务或极客模板。
- 作为用户，我希望 AI 可以重构选中模板的布局和视觉表达，而不被限制为只能调整字号、行距和页边距。
- 作为用户，我希望 AI 的结构改造先以草稿形式预览，确认保存后生成独立模板副本；原模板和其他简历不受影响。
- 作为用户，我希望在模板库中看到模板来源、当前修订号和历史版本，并能基于某个修订继续改造或恢复使用。
- 作为用户，我希望字号、行距、图标大小等微调只绑定当前简历版本，不污染同工作区的其他简历。
- 作为用户，我明确要求修改模板本体时，希望系统显示影响范围，并要求显式确认后才能覆盖。

## 业务规则

1. 用户明确选择的模板是默认基线。Agent 必须保留其视觉家族、主要视觉语言和结构意图；“应用模板”不等于“换模板”。
2. 模板改造包含两层：参数调优（字号、行距、边距、间距、颜色、图标）和结构改造（模块顺序、布局、组件变体、信息密度、CSS）。两者都可以基于当前模板进行，但持久化隔离方式不同。
3. 参数调优默认绑定当前简历版本；结构或 CSS 改造默认生成当前模板的可编辑副本。内置模板始终不可变。
4. AI 不得静默调用其他模板 ID 替代用户选择。只有用户明确要求更换，或当前模板验证失败且无法承载内容时，才允许提出切换，并说明原因。
5. AI 默认不得覆盖已有自定义模板。覆盖模板本体是高影响操作，必须由用户明确要求，并在工具调用中显式声明。
6. 另存为模板副本后，当前简历才能切换到新模板；复制失败、校验失败或保存失败时，继续使用原模板。
7. 旧版工作区数据必须可读取。旧的工作区级 presentation 覆盖可以作为兼容回退，但新保存应优先写入简历版本作用域。
8. 草稿预览不等于持久化模板。只有用户点击“保存版本”“另存为模板”或明确要求写入时，才创建持久化记录。
9. 模板库中的副本必须保留来源模板和修订谱系；恢复历史版本应生成新的当前修订或新的副本，不得静默删除历史记录。
10. 模板库应区分“应用到当前简历”“基于此模板改造”“另存为独立模板”和“查看版本”，避免用户误以为切换模板会修改模板。

## EARS 验收标准

- 当用户选择一个模板并要求把简历加入其中时，系统应以该模板为渲染基线，并在 Agent 可见指南中明确禁止静默换模板。
- 当 Agent 需要改变模块布局、组件变体、信息密度或 CSS 时，系统应先创建该模板的草稿/副本，且原模板文件内容不变。
- 当 Agent 只调整字号、行距、页边距、模块间距、颜色或图标位置时，系统应将设置写入当前简历版本作用域，而不是按模板 ID 覆盖共享设置。
- 当 Agent 尝试覆盖已存在的自定义模板且没有显式覆盖意图时，工具应拒绝写入并返回可恢复的冲突信息。
- 当用户明确要求修改模板本体时，系统应在写入前返回模板 ID、引用范围和会受影响的简历列表或可用影响摘要，并要求显式确认标记。
- 当结构改造副本尚未通过模板校验或 A4 渲染验证时，系统不得将其标记为当前简历的正式模板。
- 当用户取消草稿或切换简历版本时，系统应保留原模板、原简历和原排版设置不变。
- 当读取旧版 presentation.json 时，系统应不报错；当保存新版排版时，系统应不会删除旧字段或导致现有预览失效。
- 当用户打开模板库时，系统应展示模板当前修订、来源/派生关系和可用操作；内置模板应明确标记为不可变。
- 当用户查看模板历史时，系统应列出修订时间和差异摘要，并允许将历史修订恢复为新的当前修订或新副本。
- 当用户从模板库应用一个修订到当前简历时，系统应只更新当前简历的模板引用和排版草稿，不修改模板库文件。
- 当现有 DSH UI 未启动 MCP 时，模板库、预览、手动调整和导出链路应继续独立工作。

## 非目标

- 第一阶段不建设通用文件管理、通用代码执行或跨工作区写入能力。
- 第一阶段不要求所有历史模板立即迁移成新文件格式；采用兼容读取和渐进写入。
- 不用“强制一页”覆盖内容优先级；版面压缩必须先作用于模板承载和排版，再处理低信号文本。
