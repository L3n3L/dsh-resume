# DSH 简历插件非 AI 功能验收报告

**验收日期**：2026-09-03  
**验收视角**：普通用户首次打开 DSH 后，使用插件完成“选工作区 → 选模板 → 调排版 → 看预览 → 管理投递版本 → 导出”的一条非 AI 链路。  
**测试工作区**：`E:\vsws\deepseek-harness-plugins\jobhunt`  
**DSH 地址**：`http://127.0.0.1:3099/`  
**测试方式**：启动 DSH，通过内置浏览器逐项操作，并结合可访问性树、DOM 状态、截图和浏览器错误日志核对实际结果。

## 1. 范围与边界

本次只验收插件自身的交互、状态、文件/版本、模板、预览、排版检查、MCP 服务和导出能力，不调用任何 AI，不让 Agent 生成或改写简历内容。

为避免破坏用户数据，未执行以下动作：

- 未点击“归档”，因为它会改变本地投递版本状态，需要用户在场确认。
- 未在文件夹选择器中选择新目录，避免切换用户工作区。
- 未保存本次测试中的模板/排版草稿为新版本。
- 未点击“导出 PDF”，因为它会进入系统打印流程，当前验收使用内置浏览器，不能安全接管系统打印选择。

## 2. 验收结论

结论：**核心非 AI 链路可以使用，但当前不建议作为稳定版本直接交付。**

模板、手动排版、版本列表、MCP 启停和 HTML 下载基本可用；不过“切换投递版本后排版指标可能永久停在测量中”属于核心验收信息失效，且伴随前端异常日志，应优先修复。模板分类中的 Geek 筛选也存在明确的功能错误。

## 4. BUG-01 复现详情：版本切换后指标卡死

**复现步骤**：

1. 进入预览，当前选择 `companies/AI产品经理/preview.html`。
2. 选择 `companies/我的投递版本/preview.html`，等待指标完成；页面显示“留白 44% · 1 页”。
3. 再选择 `companies/AI产品经理/preview.html`。
4. 等待约 4 秒以上，观察顶部排版指标。

**实际结果**：状态一直是“测量中 · 排版指标”；预览画面视觉上存在，但页数节点不再生成，用户无法知道当前是否满足一页要求。

**浏览器错误日志**：

```text
Uncaught TypeError: Failed to execute 'observe' on 'MutationObserver': parameter 1 is not of type 'Node'.
TypeError: Cannot read properties of null (reading 'parentElement')
  at http://127.0.0.1:3099/plugins/dsh-resume/client.js?rev=cc7c58836e08:3268:330
```

**初步判断**：版本切换触发预览 iframe / 观测节点重建，旧回调或 MutationObserver 在目标节点已被卸载后继续执行。建议在切换前断开旧 observer，切换后确认目标节点存在再 observe；iframe load 回调也不应从已卸载节点读取 `parentElement`。同时给测量流程增加超时和失败态，不能让用户永久看到“测量中”。

## 5. BUG-02 复现详情：Geek 分类与标签不一致

**复现步骤**：

1. 打开模板库。
2. 点击“Geek”分类。

**实际结果**：显示“这个分类暂时没有模板”，但“全部”列表中的“极客实验室”卡片显示 `基础布局 · 单栏 · Geek`。

**初步判断**：筛选逻辑使用的类别值与模板卡片展示/数据中的 `Geek` 值不一致，可能是大小写、规范化或分类字段映射问题。应统一由同一份标准化 tag 集合驱动筛选和展示，并补一条分类回归测试。

## 6. 用户体验评价

### 做得好的地方

- DSH 左侧入口到简历工作台的路径短，用户可以直接进入工作区、预览和模板库。
- 模板库卡片信息层级清楚，比较上限为 3 张，符合“先比较再应用”的心智。
- 手动排版不改写 Markdown，布局参数与图标参数分开，且都有独立默认值，误操作可恢复。
- 版本管理能正确列出当前生成的 `AI产品经理` 投递版，改名和另存为取消不会产生脏数据。
- MCP 默认关闭、显式启停、端点和复制配置反馈清楚，没有偷偷占用本地服务。
- HTML 下载会给出成功反馈，且没有离开当前预览页面。

### 最影响用户信任的地方

- 一页简历的核心指标不是稳定结果：用户看到预览，却可能看不到页数和留白，这会迫使用户反复刷新甚至大刷新。
- 排版检查与预览指标存在不一致时，没有说明“当前指标来自哪一次测量、是否已完成、是否可信”。
- 模板分类出现“标签存在但筛选为空”，用户会直接判断模板库坏了。
- 模板工坊的编辑、校验、保存关系较复杂，若校验按钮偶发无反馈，用户很难判断是没有执行还是执行失败。

## 7. 建议修复优先级

1. **先修 BUG-01**：把预览测量做成可取消、可重入、有超时、有失败态的状态机；切换版本时清理旧 iframe/observer，保证任何一次切换最终都得到页数指标或明确错误。
2. **修 BUG-02**：统一模板分类 tag 的规范化和值映射，补齐 Geek、空分类和大小写回归测试。
3. **统一指标口径**：预览、排版检查、保存版本使用同一个测量结果和同一个“完成/失败/过期”状态，避免出现“1 页”和“2 页”同时可信的情况。
4. **补齐桌面边界验收**：小窗口、系统缩放、文件夹选择器、导出 PDF、归档确认、模板工坊 CSS 校验和另存为模板完整闭环。
5. **增强保存前提示**：有未保存草稿时，刷新预览、切换版本、应用模板等可能丢弃草稿的动作应明确说明影响范围，并区分“当前草稿”和“磁盘已保存版本”。
